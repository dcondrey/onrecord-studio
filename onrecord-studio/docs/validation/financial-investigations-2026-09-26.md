# Financial investigation validation — September 26, 2026

The dashboard's **Spending and outcomes** view runs native, deterministic investigations against retained analytical tables. It automatically recognizes the official City of San Diego operating-budget and actual-expenditure exports. Other imported ledgers are connected through a column-mapping editor that lists their real columns. A mapping must establish currency and agency; matching account or contract codes alone cannot join different jurisdictions.

## Acceptance coverage

| Roadmap item | Implemented behavior | Evidence and boundary |
|---|---|---|
| 1 — Trace spending to services and outcomes | Separate cited appropriation, executed contract, amendment, payment and outcome stages; identify missing links; do not add stage totals together. | Native SQL integration fixture follows mapped tables from appropriations to a restricted service-capacity scenario. Missing deliverables remain an acquisition gap, not a finding that services failed. Contract balances cover the retrieved fund and periods and are not a certification of contract-wide available authority. |
| 6 — Reconcile budget definitions | Distinct adopted, revised, actual and encumbered amounts; exact decimal arithmetic; fiscal-year/fund/account/cost-center/program/currency/agency grain; effective-period account crosswalks; transfer warnings, restrictions, and explicit one-time/recurring/mixed/unknown funding duration. | Replay checks saved real San Diego account differences. Conflicting crosswalks, partial sources and missing counterpart values withhold derived totals. Funding duration participates in the reconciliation grain; incompatible classifications cannot silently join. Unrecorded or unrecognized duration remains unknown. |
| 7 — Audit contracts and payments | Detect repeated transaction rows, conflicting transaction identities, distinct paid transactions sharing an invoice, retrieved executed-ceiling exceedances and missing outcome links. Compare compatible observed unit costs. | Identical transaction records count once. Conflicting postings withhold payment totals. Findings carry alternative explanations and the next records or tests needed; they do not label a vendor fraudulent. |
| 13 — Compare service outcomes | Require matching agency, currency, metric, population, period and units for cost comparisons. Rates also require compatible denominator units. Preserve a measured zero separately from missing values. | Native regression tests reject incompatible populations, periods, metrics and denominators. Capital costs, case mix, service quality and accounting boundaries remain possible explanations for cost differences. |
| 15 — Evaluate policy scenarios | Recompute current source data natively; calculate revised minus actual minus encumbered; require explicit eligible fund restrictions and same agency/currency; derive conditional capacity from original observed quantity and cost. | Missing restrictions, incompatible evidence, unavailable funding or changed source identities block the calculation. Every estimate is explicitly limited to the selected fiscal year; one-time or unknown funds cannot imply recurring capacity. The range uses comparable retrieved observations; it is not a forecast, statistical confidence interval or legal-transfer authorization. |

Each evidence entry retains the analytical snapshot ID, source URL, original source hash, executed-query identifier, result columns and exact result row. Query SQL is stored once per report. Reports are recomputed, not persisted as stale financial totals. Mapping configuration is the only new stored state; an old-schema upgrade test verifies that existing analytical records survive creation of that configuration table.

## Autonomous use

The research planner receives bounded deterministic financial leads, supporting rows, query SQL and actionable acquisition gaps. The context explicitly requires re-executing the source queries before using a lead as cited research evidence. Its content is stable between unchanged runs, and mapping changes update the scheduler fingerprint. Personal-information masking applies to model context; the local evidence view retains the source rows used in the calculation.

The investigator can inspect exact evidence for each lead, choose an actual ingested scope, change a source mapping, view missing records, and test a conditional service scenario. A response started for an earlier scope or scenario input is discarded after that identity changes.

## Tests and real-source replay

There are 14 native financial tests: nine analysis tests and five storage tests. They cover exact amounts beyond JavaScript's safe integer range, null versus zero, fiscal/account crosswalks, agency isolation, funding duration and one-period scenario limits, duplicate payment alternatives, source incompleteness, compatible outcome denominators, restricted scenarios, existing-schema upgrades, current-source identity, and real SQL over mapped contract/payment/outcome tables.

The offline San Diego replay uses the preserved query rows in [finance-comparisons.json](finance-comparisons.json), created by the earlier verified live ingestion of approximately 1.2 million financial rows. It independently reconstructs every returned account comparison and missing counterpart. For example, the retained Homelessness cost-center/account row has adopted funding of $11,332,872 and actual spending of $769,568, a difference of −$10,563,304. Revised authority, encumbrances and available funding remain unknown. This is an account-level example from the archived scope, not a new live fetch or a department-wide conclusion. See the [live finance dossier](live-finance-dossier.md) for source identity and interpretation.

All 14 financial native tests pass within the final normal suite (434 passed, one ignored). Five financial frontend tests pass, including two scope/input race tests. Both race tests fail when their production guards are removed. An isolated native mutation that disables the source-identity guard fails on the changed-snapshot assertion; the restored normal build passes. Targeted ESLint, the integrated frontend suite (178 passed), and the production build pass after agency isolation and funding-duration handling were added. The complete quality-gate record is in the [workbench validation record](investigative-workbench-2026-09-26.md).

The mapped contract/outcome integration fixture tests actual production queries and calculations with synthetic records. It does not claim that unacquired San Diego payment, encumbrance, amendment or service-outcome ledgers exist locally. Those gaps remain visible until the user imports the records or autonomous acquisition obtains them.
